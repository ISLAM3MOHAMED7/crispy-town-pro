Crispy Town POS — حزمة تجهيز الشات الموحد
==========================================

الحالة الحالية
--------------
- تم تحديث شاشة الشات في index.html لتكون صندوق وارد واحدًا للقنوات الثلاث.
- تم إضافة عميل API يعرض المحادثات والرسائل ويرسل الردود من خلال خادم آمن.
- تم إنشاء خادم Node.js يستقبل Webhooks من Meta، ويحفظ المحادثات والرسائل في SQLite، ويرسل الردود عبر Graph API.
- لم يتم الاتصال بحساباتك الحقيقية بعد، ولم يتم اختبار الرسائل الحية؛ لأن بيانات تطبيق Meta والتوكنات والاستضافة غير متاحة في المحادثة. لا تعتبر القنوات مفعلة قبل إكمال الخطوات أدناه.

المتطلبات
---------
1) Node.js 20 أو أحدث + نطاق HTTPS عام ثابت للخادم.
2) تطبيق Meta في developers.facebook.com مع تفعيل منتجات Messenger وInstagram Messaging وWhatsApp.
3) صفحة Facebook بصلاحية إدارة، وحساب Instagram Professional مربوط بالصفحة.
4) WhatsApp Business Platform / Cloud API ورقم هاتف مفعّل.
5) إكمال صلاحيات Meta ومراجعة التطبيق عند الحاجة، وتفعيل Webhooks لكل منتج.

تشغيل الخادم
------------
1) افتح مجلد server.
2) انسخ .env.example إلى .env.
3) املأ القيم الحقيقية، واختر كلمة مرور قوية لـ INBOX_PASSWORD.
4) ضع إصدار Graph API الفعلي المدعوم في GRAPH_API_VERSION (مثل vXX.X بعد التحقق من لوحة Meta؛ لا تترك القيمة التجريبية).
5) من الطرفية داخل server نفّذ:
   npm install
   npm start
6) اربط النطاق العام بالخادم واجعل مسار Webhook هو:
   https://YOUR-DOMAIN/webhooks/meta
7) أدخل META_VERIFY_TOKEN نفسه في إعداد Webhooks داخل Meta، ثم اشترك في الأحداث المطلوبة لكل قناة.
8) افتح POS من نفس النطاق/الأصل الذي يخدم API، ثم ادخل إلى الشات واضغط «دخول الشات» واكتب INBOX_USER وINBOX_PASSWORD.

متغيرات الربط المطلوبة
----------------------
FACEBOOK_PAGE_ID + FACEBOOK_PAGE_ACCESS_TOKEN
INSTAGRAM_ACCOUNT_ID + INSTAGRAM_PAGE_ACCESS_TOKEN
WHATSAPP_PHONE_NUMBER_ID + WHATSAPP_ACCESS_TOKEN
WHATSAPP_BUSINESS_ACCOUNT_ID (لإعداد الاشتراك في Webhooks من لوحة Meta)
META_APP_SECRET + META_VERIFY_TOKEN + GRAPH_API_VERSION

ملاحظات مهمة قبل التشغيل الفعلي
-------------------------------
- لا تضع Access Tokens أو App Secret في HTML أو ترسلها داخل المحادثة. تحفظ على الخادم فقط.
- ردود Messenger وInstagram تخضع لنافذة المراسلة وسياسات Meta. رسائل WhatsApp تخضع لقواعد نافذة خدمة العملاء والقوالب المعتمدة عند اللزوم.
- الرد باسم الموظف في هذه النسخة يسجل الاسم الذي يكتبه الموظف في خانة «اسم الموظف»؛ لم يتم بناء تسجيل دخول موظفين موحد/مصادقة أدوار مستقلة داخل POS الحالي.
- الملفات المرفقة/الصور/الصوت تظهر كرسالة غير نصية placeholder في هذه النسخة؛ دعم تنزيل وعرض الوسائط يحتاج إضافة لاحقة.
- قبل فتح النظام على الإنترنت، ضع HTTPS، وقيّد الوصول إلى لوحة POS، واضبط كلمات مرور قوية ونسخًا احتياطيًا لملف server/inbox.sqlite.
- هذا الخادم نقطة بداية تنفيذية تحتاج إكمال إعداد تطبيق Meta وربط حساباتك واختبار كل قناة فعليًا. لا يوجد ادعاء بأن الربط الحي تم بالفعل.
